# riskpipe — пакетная оценка риска заказчиков

Каждое утро на вход приходит список заказчиков (например, из свежих закупок вашей отрасли), на выходе — карточка
на каждого: **светофор** (🔴 не брать без риск-менеджера · 🟡 в работу с проверкой · 🟢 в работу · ⚪ данных мало),
пояснение по флагам со ссылкой на каждый факт, граф связей и, для самых рискованных, глубокий разбор с критиком.

Риск заказчика здесь — риск потратить время или не получить оплату: банкротство и ликвидация, иски поставщиков,
долги у приставов и налоговой, падение выручки, недостоверность в ЕГРЮЛ, то же самое у материнской компании,
дочек и компаний тех же владельцев.

## Как это устроено

```
вход (CSV)  →  сбор фактов  →  база утверждений  →  граф связей  →  правила  →  карточки
               ФНС, ГИР БО,     у каждого факта    владельцы, дочки,  rules.yaml   cards.json, report.md
               Checko API,      ссылка, класс      адрес, суды,       (цвет —      + глубокий разбор
               новости          источника, срок    волна фронтира     код, не LLM)   красных и жёлтых
```

Принципы:

- **Цвет считает код по правилам**, а не модель. LLM работает только там, где без неё нельзя: СМИ и глубокий разбор.
- **Факт и гипотеза разделяются кодом по классу источника:** госреестр → «факт», агрегатор → «факт (агрегатор)»,
  СМИ → «гипотеза». Гипотеза сама по себе даёт максимум жёлтый. Красный флаг агрегатора сверяется с ФНС.
- **Нет источника — нет утверждения.** Запись без ссылки база не принимает. ИНН проверяется контрольной суммой;
  ИНН на странице источника должен совпасть с запрошенным (защита от подмены карточек).
- **«Не нашли» ≠ «чисто».** Зелёный — только без флагов и при проверке ≥ 4 из 5 каналов; иначе серый.
- **База утверждений, а не файл на кейс.** Повторный прогон перезапрашивает только протухшее; узлы людей и связей
  переиспользуются между заказчиками.
- **Правила поиска mOS** (папка `methodology/`): суды — не количество, а состав; связи — закрытым словарём;
  витрины не выкачиваются; поиск волнами по фронтиру; критик для выводов.

## Источники

| Канал | Источник | Ключ | Примечание |
|---|---|---|---|
| Статус, процедура банкротства, учредители, руководитель, недоимка, недостоверность, адрес | ФНС «Прозрачный бизнес» (pb.nalog.ru) | нет | официальный; пауза между запросами, капча не обходится |
| Финансы (выручка, прибыль, капитал) | ГИР БО (bo.nalog.gov.ru) | нет | официальный |
| Суды (дела в роли ответчика за 12 мес, роли, суммы, исход), ФССП, санкции, дочки, правопреемство | Checko API | `CHECKO_API_KEY` | бесплатно ~100 запросов/сутки ≈ 33 компании |
| Тексты судебных актов | sudact.ru | нет | единичное чтение 1–2 актов по номеру дела |
| Новости | RSS Google News | нет | классифицирует LLM |
| КАД, Федресурс, ЕИС | — | — | открываются только с российского IP; коннекторов пока нет, канал помечается «не открылось» |

Веб-страницы агрегаторов (Companium, Checko) по списку не читаются — это правило mOS; включается явно флагом
`--web-aggregators` и только для отладки.

## Быстрый старт

Нужен Python 3.10+.

```bash
git clone https://github.com/SoapMaker101/riskpipe.git
cd riskpipe
python -m venv .venv && . .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                  # впишите CHECKO_API_KEY
python -m pytest eval -q                              # офлайн-проверки
python -m pipeline.run --input input/example.csv --run-id demo
```

Результат — в `out/demo/`: `cards.json` (карточки), `report.md` (отчёт для менеджера в порядке «в работу → с проверкой →
не брать → дособрать»), `deep/<ИНН>.md` (глубокие разборы), `run.log`, `http_journal.json` (каждый запрос с url).

Входной CSV: `name,inn,query,origin` — название, ИНН (если есть), строка для поиска по названию, откуда компания
в списке. Без ИНН компания опознаётся по названию в ЕГРЮЛ: единственное действующее совпадение или, среди тёзок,
кандидат с ОКВЭД вашей отрасли (`identification.industry_okved`), с пометкой «гипотеза, сверить ИНН».

## LLM-шаги (необязательные)

Без LLM конвейер работает полностью: сбор, граф, правила, карточки. LLM добавляет два слоя:

- **Классификатор СМИ** — заголовки новостей → события «банкротство / неоплата / уголовное дело / остановка
  производства / смена собственника / санкции». Код принимает пункт, только если цитата дословно есть в заголовке
  и событие вредит именно этой компании.
- **Глубокий разбор** (`deep/`) — для красных, затем жёлтых по тяжести флагов, в пределах бюджета прогона:
  код собирает материалы (акты sudact по номерам дел из графа, новости, страницы по ссылкам, найденным поиском),
  дешёвая модель вынимает факты с дословными цитатами (код их сверяет), средняя пишет сводку «что случилось и
  что проверить», отдельный критик ищет слабые места. ~20–35 тыс. токенов на компанию. Цвет разбор не меняет.
  Разбор одной компании вручную: `python -m deep.analyze --inn <ИНН>`.

Как подключить (одно из двух):

1. **Claude Code CLI** (`claude`), авторизованный под вашей подпиской, — используется автоматически, если найден в PATH.
2. **Anthropic API**: `ANTHROPIC_API_KEY` в `.env` и `pip install anthropic` — для классификатора СМИ.

Бюджеты и модели — в `scoring/rules.yaml`, раздел `deep`. Отключить: `--no-deep`.

## Настройка

- `scoring/rules.yaml` — все пороги, веса графа, тяжесть флагов, бюджеты LLM, отраслевые ОКВЭД. **Пороги по умолчанию
  подобраны на небольшой выборке — перед боевым использованием проверьте их на своей размеченной выборке.**
- `.env` — `CHECKO_API_KEY`, необязательно `MOS_ROOT` (взять методику из исходников mOS вместо `methodology/`),
  `ANTHROPIC_API_KEY`.
- Флаги `pipeline.run`: `--offline` (без сети), `--no-frontier`, `--no-deep`, `--deep-limit N`, `--web-aggregators`,
  `--today YYYY-MM-DD`, `--db`, `--input`, `--run-id`.
- Импорт готового графа связей в формате mOS (`graph.jsonl`): `python -m collectors.mos_graph <файл или папка>`.

Повторный запуск с тем же `--run-id` продолжает с чекпойнта (очередь в SQLite, статус на каждую компанию).

## Развёртывание на сервере

Коротко: `sudo bash deploy/install.sh` ставит venv, зависимости, `.env`, прогоняет тесты и включает systemd-таймер
на 06:00. Подробно, включая требования к сети (российский IP для КАД/Федресурса/ЕИС), cron и LLM на сервере —
[docs/DEPLOY.md](docs/DEPLOY.md).

## Структура

| Папка | Что внутри |
|---|---|
| `core/` | ИНН/ОГРН и номера дел, класс источника, HTTP с лимитером по хосту и кэшем, `.env` |
| `collectors/` | `pb_nalog` (ФНС), `bfo` (ГИР БО), `checko_api`, `news`, `mos_graph` (импорт графа в формате mOS `graph.jsonl`), `snapshot` (необязательный снимок), `checko`/`companium` (веб, только по флагу), `unavailable` (пробы закрытых каналов) |
| `db/store.py` | база утверждений (entity, statement, edge, check_log), прогоны, очередь, карточки |
| `graph/` | раскрытие связей через ИНН людей, волна фронтира, дела как узлы графа, перенос риска с весами |
| `scoring/` | `rules.yaml`, правила светофора, перекрёстная проверка, пояснения |
| `cards/` | схема и валидатор карточки, markdown-отчёт |
| `llm/` | классификатор СМИ |
| `deep/` | глубокий разбор: материалы, веб-указатели, методика, критик |
| `methodology/` | правила поиска mOS: источник, граф связей, суды, исследователь, критик, правовые рамки |
| `pipeline/run.py` | утренний прогон |
| `eval/` | офлайн-тесты на синтетических данных (вымышленные компании, ИНН с префиксом 99) |
| `deploy/` | установка на сервер, systemd-сервис и таймер |

## Ограничения и правовые рамки

- Капча, антибот и закрытые витрины **не обходятся** — канал помечается «не открылось». Чтение публичных страниц —
  единичное, не выкачивание баз списками (см. `methodology/sources.md`, раздел о праве).
- ФИО учредителей и руководителей — персональные данные (152-ФЗ): храните базу и отчёты соответственно.
- Агрегаторы — вторичный источник: красное «по агрегатору» в карточке помечено «подтвердить в первоисточнике».
- Без российского IP недоступны КАД, Федресурс и ЕИС; суды и ФССП тогда идут только через Checko API.
- Пороги и веса — отправная точка, а не утверждённая методика риск-менеджмента.
